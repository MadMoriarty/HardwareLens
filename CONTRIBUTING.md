# Contributing

Read [the build guide](docs/build.md), run core tests and a Release build, and keep changes focused. Explain the user-visible problem, implementation, and validation in your pull request.

Use synthetic or carefully reviewed examples in public issues. Never attach machine inventories, recordings, usernames, serial numbers, MAC addresses, or private log files. Report vulnerabilities through [the security policy](SECURITY.md).

Show unavailable data explicitly rather than substituting zero. Preserve standard-user launch, explain Windows access failures, and keep management actions deliberate. Update guides when behavior changes. Native functionality needs evidence from Windows testing; mark untested environments clearly.

Contributions are licensed under the repository's MIT license. Preserve dependency notices.
